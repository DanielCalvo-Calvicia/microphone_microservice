## Goal

Run the container with `MICROPHONE_BACKEND=sim` and call every endpoint through the published address, as Brain would.

## Steps

1. With the maintainer's yes, start the container (through the tool, or the `docker run` line it prints). Read the deploy output: `microphone: healthy and available, warning: <reason that says sim>` (T-06.3), not a failure after 15 s.
2. `GET /health` 200; `GET /available` 200 with `is_available: true` and the reason; the log has the line that says the simulated backend is active (T-02.3); the bind inside the container is `0.0.0.0` (the tool sets it for Docker) and the published address, not an assumed `127.0.0.1`, was used.
3. `POST /start` (default format 16000 Hz, 1 channel, chunk 1024), `GET /stream` read for the pattern's duration: `stream_started`, at least one `utterance` event (count the lines; do not print `bytes_base64`) with a length that matches the pattern, then `POST /stop` and see `completed`. A second `POST /start` while capturing is 409; `POST /stop` when idle is 409; a `sample_rate` mismatch is 422.
4. The pacing (Q02-3): the time between the first and the last chunk is close to the pattern's duration, not instant.
5. Run the pipeline check of the workspace beside it for contrast: `brain_microservice\windows\Scripts\python.exe -m pytest contracts\tests -q` (it uses its own fake and does not use this container).

## Acceptance criteria

Every call answers as listed; the utterance count and length are recorded; the log has no audio and no secret.

## Verification

Status codes, counts and timings, in *Result*.

## Result (2026-11-10)

The container log has the warning `Microphone backend is simulated` once and 0 lines that match key, secret, token or password.
