## Goal

Show that the container survives a restart and a recreate and that shutdown is clean.

## Steps

1. `docker --context desktop-linux restart oblivion-microphone`: healthy again; `/available` as before.
2. Recreate it through the tool (`oblivion.py update` or a second `deploy`; the tool does `docker rm -f` then `docker run`): healthy; the generated `.env` is mounted again (read-only, if T-06.1 is built).
3. Capture running, then `docker stop`: time it. The process is PID 1 (`python main.py`); uvicorn gets SIGTERM, `_cleanup` stops the stream. Expected: it ends in well under Docker's default 10 s; the log has `Server stopped; releasing microphone` and no kill. Record the exit code (`docker inspect`).
4. Start it again and check that the capture is idle (`POST /start` works, not 409).

## Acceptance criteria

Steps 1 to 4 behave as written; the time of `docker stop` and the exit code are recorded.

## Result (2026-11-10)

`docker restart oblivion-microphone`: healthy again in **0.9 s**, `/available` as before. **Recreate** through the tool (a second `deploy`, which does `docker rm -f` and `docker run`): **31.6 s** (the image is rebuilt from cache), the container id changed, healthy at once, the `.env` mounted again read-only. **`docker stop` with a capture running** (`/start` called, **no** `/stream` consumer): **0.69 s**, exit code **0**, not OOM-killed, the log has `Shutting down`, `Server stopped; releasing microphone` and `Cleanup finished`; `docker start`: healthy in 0.9 s and `POST /start` **200** (the capture is idle again, not 409). **Finding (not fixed):** with a `/stream` consumer connected, as Brain is, `docker stop` waits for the whole 10 s grace period and is then killed (exit code 137, 10.46 s): uvicorn's graceful shutdown waits for the open request, so the lifespan cleanup (`Server stopped; releasing microphone`) never runs; without a consumer it stops in 0.69 s with exit code 0. A real device is released by the operating system when the process dies, but the clean path is not taken. (A probe with the default 10 s grace period; Docker's `docker stop -t` was not raised for the microphone.) The first part of the plan is therefore proven for a stop without a consumer, and not for the normal case of Brain being connected: that is a finding for the maintainer, not fixed here.

## Addendum (2026-11-10): the finding was fixed

**Fixed 2026-11-10:** `main_flow/http.py` passes `timeout_graceful_shutdown=GRACEFUL_SHUTDOWN_SECONDS` (5 s) to uvicorn, which now cancels the open requests after 5 s and runs the lifespan cleanup. Test first (`tests/main_flow/test_shutdown.py`, failing on the old code), 4 of 4 one-line mutations caught. Re-run in Docker with Docker's default 10 s grace period: with a `/stream` consumer connected `docker stop` took **5.69 s** and ended with exit code **0**; the log shows the stream terminated, `Application shutdown complete`, `Server stopped; releasing microphone` and `Cleanup finished`; the client's stream ended cleanly. uvicorn logs the cancelled request as an ERROR line (`Exception in ASGI application`, `CancelledError: Task cancelled, timeout graceful shutdown exceeded`): expected noise. This closes the part of the plan that was not proven: a stop with Brain connected.
