> The workspace rule: `deployment/` is its own repository and has its own `CLAUDE.md`; read it before editing. Ask the maintainer before touching another repository, and do not commit there.

## Goal

Show that a machine without a microphone can be deployed and run the pipeline on `sim`, and keep the deployment documents true.

## What it must do

1. **Preset (decided in T-02.1):** if the maintainer wants a layout that starts on `sim`, add `MICROPHONE_BACKEND = "sim"` under `[services.microphone.env]` of the catalogue (as stepper does with `MOCK_HARDWARE = "1"`), and say in `config/local/microphone.toml` documentation that the machine with the sound card sets `real`. If the maintainer wants no preset, skip this step and say so in the Resolution.
2. Regenerate `deployment/config/services/microphone.toml` with `brain_microservice\windows\Scripts\python.exe deployment\scripts\env_inventory.py --write`.
3. Update `deployment/docs/DEPLOYMENT.md` (the microphone variable table).
4. Add a test in `deployment/tests/` that a layout with `MICROPHONE_BACKEND=sim` passes the readiness check without a device (the check reads `/available`; use the existing fakes of `http_health`).
5. Run the full pipeline check from the workspace root: `brain_microservice\windows\Scripts\python.exe -m pytest contracts\tests -q`, and the `deployment` suite (about 140 s).
6. Optionally, an end-to-end run with the real microphone service on `sim` instead of the fake `SineStream`: only if the maintainer asks.

## What it must not do

- Change the code default of the service.
- Edit `.env` files, the venvs or generated `contracts` folders.
- Commit or push in any repository.

## Acceptance

The `deployment` and `contracts` suites pass; the catalogue, the generated toml and the manual agree with `.env.example`; this repository's `docs/deployment/deployment.md` and `docs/security/security.md` (a simulated device is not a security feature) mention the preset if one exists.

## Result (2026-11-10)

Done (steps 1 to 4 are T-06.2, T-06.3 and T-06.5, all done). **Step 5, the pipeline check:** `brain_microservice\windows\Scripts\python.exe -m pytest contracts\tests -q` from the workspace root: **84 passed, 18 skipped** in 90 s (10 need a real LLM, 8 miss requirement files: the same skips as on 2026-11-06), run after the microphone, `deployment` and speaker-side changes to that point; ports 7998 to 8005 were free before and after. That suite uses its own fake `SineStream`, not the new adapter, so it shows only that nothing else broke. **Step 6, the real service on `sim` (no sound device, no sound):** `scratchpad/e2e_sim.py` copied the working tree into a scratch folder without any `.env*`, wrote a made-up `.env` there (`SERVICE_PORT=8101`, `MICROPHONE_BACKEND=sim`, nothing of it in the process environment), started `python main.py` and called every endpoint: the service listened on the port that only the `.env` carried (the `.env` loading works end to end); `GET /health` 200 `healthy: true`; `GET /available` 200 `is_available: true` with `reason` = "simulated microphone (MICROPHONE_BACKEND=sim): a generated signal, not a real device"; `POST /start` 200 (16000 Hz, mono, pcm16, chunk 1024); a second `POST /start` 409; `GET /stream` gave `stream_started` and then one `utterance` **9.7 s after the start** (the tone is about 5.1 s and the cutter needs about 3.8 s of smoothed silence plus the silence limit to end it, which is exactly the merge finding F10) of **153,600 samples (9.6 s at 16 kHz)**; `POST /stop` 200 and a second `POST /stop` 200 (idempotent); `/available` after the stop still true; the log has the warning `Microphone backend is simulated` once; the process was terminated by the script (exit code 1 on Windows is `TerminateProcess`, not a failure of the service; graceful shutdown is T-07.3). Not run: the same with Brain in front (needs ai-agent for a reply; the pipeline check covers Brain with its own fake). The scratch folder and its log were deleted afterwards.
