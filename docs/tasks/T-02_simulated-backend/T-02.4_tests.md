## Goal

Prove that the simulated backend behaves like a device from the application's point of view, and that choosing it changes nothing else.

## Tests to write

| File | Cases |
|---|---|
| `tests/infrastructure/test_simulated_audio_capture.py` | `open_stream` at 16000 and 44100 Hz gives mono chunks of `chunk_size * 2` bytes; `check_device` is `(True, reason)` with `simulated` in the reason; `close` is idempotent and ends iteration; `on_terminated` never fires; pacing: two chunks take about twice `chunk_size / sample_rate` (use a generous tolerance, or patch `asyncio.sleep`) |
| `tests/infrastructure/test_signal_pattern.py` | The pattern has noise, tone and silence in order and repeats; amplitudes are within int16; the length of the silence exceeds the default silence limit at 16000 Hz |
| `tests/domain/test_utterance_segmenter.py` (new case, or a new file `tests/application/test_simulated_pipeline.py`) | Chunks from the simulated stream through `UtteranceSegmenter` with the default treatment give one utterance per repetition and none from the noise alone |
| `tests/infrastructure/test_config.py` | `MICROPHONE_BACKEND` default `real`, `sim`, case-insensitive, invalid value |
| `tests/composition_root/test_http_container.py` | With `sim` the container builds without `sounddevice`; `GET /available` answers `is_available: true` and a reason containing `simulated`; `POST /start`, `GET /stream`, `POST /stop` through the `TestClient` produce `stream_started`, one `utterance` and `completed` |
| `tests/architecture/test_dependency_rules.py` | No change needed; it must stay green with the new package |

## Rules

- No hardware, no `sounddevice` (the existing tests stub the module where needed; follow `tests/composition_root/test_tracing.py`).
- Tests must be fast: use small pattern constants through the adapter's constructor arguments rather than waiting for a real pattern.
- No recordings.
