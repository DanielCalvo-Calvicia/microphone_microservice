## Goal

Choose the backend from an environment variable in the composition root, report it, and document the variable everywhere.

## What it must do

- `MicrophoneConfig` gains `backend: str` read from `MICROPHONE_BACKEND` (name per T-02.1), default `real`, case-insensitive; a value other than `real` or `sim` raises a clear error at start (a config error, like the `InputTreatment` ones: add `InvalidBackend` to `domain/errors.py` only if the rule belongs to the domain; otherwise raise `ValueError` from the config, as the other parse errors do).
- `composition_root/dependencies/microphone_dependencies.py:new_audio_capture(cfg)` returns `SimulatedAudioCapture()` for `sim`, else the current `SoundDeviceAudioCapture`. This is the **only** place that decides.
- At start, `main_flow/http.py` (through the container or the config) logs one line at **warning** level with the constant message `Microphone backend is simulated` when `sim` is chosen; for `real` it logs nothing new.
- `.env.example` gets the variable with a comment: default `real`; `sim` is for a machine without a microphone and is reported by `/available`.

## What it must not do

- Change the default from `real` (unless T-02.1 says so).
- Make `application` or `domain` read the variable.
- Hide the simulated state: `/available` must show it (T-02.2) and the log must show it.

## Files

`infrastructure/config/microphone_config.py`, `composition_root/dependencies/microphone_dependencies.py`, `main_flow/http.py` (the log line, only if the container does not already log), `.env.example`, `README.md` (configuration table, status table), `docs/configuration/environment-variables.md`, `docs/api/api.md` (the `/available` reason), `docs/operations/monitoring.md` (the warning line), `docs/architecture/architecture.md` (sections 3, 4 and 12), `CLAUDE.md` (Rules), and outside this repository `deployment/docs/DEPLOYMENT.md` and `deployment/config/services/microphone.toml` (regenerate with `deployment\scripts\env_inventory.py --write`: part of T-02.5).

## Acceptance

- `MicrophoneConfig.from_env({})` has `backend == "real"`; `{"MICROPHONE_BACKEND": "sim"}` has `"sim"`; `"nope"` fails naming the variable.
- `new_audio_capture` returns the right adapter class for each value.
- The warning is logged for `sim` and not for `real`.
- Baseline of the tasks README section 3; the documents above are true.
