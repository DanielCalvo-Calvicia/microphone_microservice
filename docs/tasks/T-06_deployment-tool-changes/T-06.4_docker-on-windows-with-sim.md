## Resolution

*Answered 2026-11-09 (Q02-5 and Q02-6, "Recommended"): **keep** the rejection of Docker for an audio service on Windows and document it (no `mode = "local"` override); **and allow** it when the service's resolved backend is `sim`, so the Docker acceptance runs through `oblivion.py`. The code change below is therefore to be done, and it is the same change as the speaker's T-02.3: make it once.* (Original instruction, kept: when answered: copy each answer here with its date, update Q02; if Q02-6 is yes, the code change is: `deployment/domain/rules/host_validation.py` lets the rule pass when the service's resolved env says the simulated backend (read through the catalogue and `resolve_env`, not by name), with a test that `real` on Windows with Docker is still refused and `sim` is accepted, and `deployment/docs/DEPLOYMENT.md` says so; if no, the task is `done` with no code and T-07 names the manual route.

## Result (2026-11-10)

Done with the answers of Q02-5 and Q02-6 ("Recommended"): the rejection for `real` stays; a new catalogue key `simulated_when = { VAR = "value" }` (microphone: `{ MICROPHONE_BACKEND = "sim" }`) tells the tool that with those resolved settings the service uses no sound device. `domain/rules/hardware.py` `uses_sound_device(host, name)` judges the resolved value (never the name; an unset or unknown value counts as the real device) and is used by `host_validation` (Docker on Windows) and by `docker_runtime.start` (no `--device /dev/snd` for a simulated service on Linux). The refusal message for `real` now names the simulated alternative. A new key was needed (the plan allows keys only when a task needs one): without it the tool would have had to know the microphone by name. Tests written first (they failed with `No module named 'domain.rules.hardware'`): `tests/test_simulated_hardware.py`, 9 tests (sim is accepted in Docker on Windows, `real` and an unknown value are refused, a service without the audio flag is never an audio service, an audio service with no `simulated_when` is always refused (the speaker, until its plan adds its own), a simulated container on Linux gets no `--device`, a real one still gets `/dev/snd`, the catalogue loads the key, the manual names it). The speaker adds its own `simulated_when = { SPEAKER_BACKEND = "null" }` in its plan (speaker T-02.1/T-02.3): one mechanism for both.
