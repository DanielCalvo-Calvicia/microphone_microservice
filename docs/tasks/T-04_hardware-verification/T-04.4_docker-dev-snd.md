## Goal

Find out whether the microphone works inside the container the deployment tool builds on a Linux host, with `--device /dev/snd`.

## Background

On a Linux host the tool adds `--device /dev/snd` because the catalogue has `audio = true` (`deployment/.../docker_runtime.py`). The image has no `USER`, so it runs as root and the `audio` group is not needed inside. It has no ALSA configuration, so "the OS default input" may find no device. On a Windows host Docker cannot reach the sound card and the tool rejects `runtime = "docker"` for an audio service (`host_validation.py`); that case is not tested here.

## Steps for the maintainer

1. On the Linux host of T-04.3, set `runtime = "docker"` for the microphone in `deployment/config/local/microphone.toml` (a layout of the deployment tool; read `deployment/docs/DEPLOYMENT.md` first) and `deploy`.
2. `curl http://<host>:8000/available`. If it says no device: `docker exec` into the container and check `ls /dev/snd`, `arecord -l`; try `MICROPHONE_TARGET_KEYWORDS` with the device name.
3. Repeat the sentences of T-04.1.
4. Note what is needed to make it work (an ALSA config, `--group-add audio`, a PulseAudio socket) without changing anything in `deployment` yet.
