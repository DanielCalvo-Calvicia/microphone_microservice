## Goal

Make the defaults of `InputTreatment` right for the room and microphone of the maintainer, or confirm them.

## What it must do

- From the *Results* of T-04.1, list the symptom of each failure and the setting that addresses it:
  - clipped starts: raise `MICROPHONE_PREROLL_SECONDS` (default 0.2 since 2026-11-09, ADR-003), or lower `MICROPHONE_SILENCE_THRESHOLD` or `MICROPHONE_SPEECH_START_FACTOR`;
  - an utterance that never ends in a noisy room: raise the threshold, or check `MICROPHONE_NOISE_FLOOR_TRACKING` (a floor that stays too high in a very quiet room also hurts: turn it off);
  - a click starts an utterance: lower `MICROPHONE_VOLUME_SMOOTHING_FACTOR` (more smoothing) or raise `MICROPHONE_SPEECH_START_FACTOR`;
  - answers feel slow: lower `MICROPHONE_SILENCE_LIMIT_SECONDS`;
  - STT accuracy: `MICROPHONE_RESAMPLE_TO_HZ=16000`.
- Prefer to change the **machine's local settings** (`deployment/config/local/microphone.toml`) over the code default; change the code default only if the maintainer says the new value is right for every machine (a decision, recorded in a dated update of ADR-003).
- If a default changes: `domain/value_objects/input_treatment.py`, `.env.example`, `README.md`, `docs/configuration/environment-variables.md`, `docs/architecture/architecture.md` (sections 7 and 8), `docs/setup/08_domain-modeling.md`, `docs/setup/14_risks-and-debt.md`, `tests/domain/test_input_treatment.py` (and any test that relies on the old value), `deployment/docs/DEPLOYMENT.md` and `deployment/config/services/microphone.toml` (regenerate).

## What it must not do

- Change a default without a result from T-04.1 that supports it.
- Test "in the room" with unit tests; the unit tests only check the values and the rules.

## Acceptance

The defaults are confirmed or changed with a recorded reason; the documents agree; the baseline of the tasks README section 3 passes; the maintainer confirms on the real microphone that the symptom is gone (a second manual run, recorded in *Results*).
