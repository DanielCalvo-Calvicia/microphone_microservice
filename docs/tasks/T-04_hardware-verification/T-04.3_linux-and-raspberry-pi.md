## Goal

Run the service natively on Linux and on a Raspberry Pi, with `requirements.linux.txt`, and record what works.

## Steps for the maintainer

1. System packages: `libportaudio2 portaudio19-dev`; the user in the `audio` group (`sudo usermod -aG audio $USER`, log in again). Python 3.12 or newer for the service venv (the interpreter path is `windows/bin/python`, the folder keeps its name).
2. Install: `pip install -r requirements.linux.txt` (or the deployment tool: `deploy` with the microphone on this machine). Note any package that fails to build on the Pi (numpy and sounddevice wheels, PortAudio).
3. `python main.py`, then `curl http://127.0.0.1:8000/available`. Note `is_available` and `reason`; list the devices the kernel sees (`arecord -l`) next to what the service chose.
4. Repeat the sentences of T-04.1 and note the same things. On the Pi note CPU use while streaming and whether `MICROPHONE_RESAMPLE_TO_HZ=16000` (linear interpolation in the service's CPU) is affordable.
5. Run the unit tests on that machine (`python -m pytest`), because `tests/composition_root` stubs `sounddevice`.

## What the assistant does

Prepares this checklist, checks `requirements.linux.txt` against `requirements.windows.txt` (identical today), and records the *Results*. If a Linux-only problem appears, it opens a task with the observation; it does not guess a fix.
