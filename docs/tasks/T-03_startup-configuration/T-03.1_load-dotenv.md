## Goal

The service reads its own `.env` the way stt and stepper do, so a hand start and a Docker start behave like a deployed start, and the deployment tool no longer needs the special path.

## What it must do

1. Add `python-dotenv>=1.0.1` to `requirements.windows.txt` and `requirements.linux.txt` (runtime).
2. In `main_flow/http.py`, before `ServerConfig.from_env()` is called: `_ENV_FILE = Path(__file__).resolve().parent.parent / ".env"` and `load_dotenv(dotenv_path=_ENV_FILE)`. A missing file is fine; `override` stays false so the process environment wins (the deployment tool passes values this way). Read stt's and stepper's `main_flow/http.py` first and match them; do not copy anything else from them.
3. A test (`tests/infrastructure/test_env_loading.py` or in `tests/composition_root/`): write a temporary `.env` in a temp directory, load it through the same helper the entry point uses (extract the two lines into a small function in `main_flow/http.py`, e.g. `load_environment(path)`, so the test does not start uvicorn), and assert that a variable from the file is visible, that one already in the environment is not overwritten, and that a missing file does nothing. Never read the real `.env`.
4. In `deployment/` (after the maintainer's answer, see T-03.3): `dotenv = true`, `tests/test_env_file_only.py`, `docs/DEPLOYMENT.md`; run the deployment suite (about 140 s).
5. Documents: `docs/configuration/environment-variables.md` (the paragraph that says the service does not load `.env`), `README.md` (Run), `CLAUDE.md` (Rules: "The service does not load `.env`"), `docs/setup/06_inputs-and-outputs.md`, `docs/setup/09_technology.md`, `docs/setup/11_runtime-and-deployment.md`, `docs/architecture/architecture.md` section 12 item 5, `docs/deployment/deployment.md` (the `dotenv` row), FR-16, PR-002.

## What it must not do

- Open, print or copy `.env`, `.env.staging` or `.env.production`; put a secret in a test (the temporary file holds a dummy variable).
- Change how variables are named or defaulted.
- Commit or push, in either repository.

## Acceptance

The new test passes; the whole suite, ruff and mypy are green; the deployment suite passes with `dotenv = true`; a start with `SERVICE_PORT` set only in the `.env` listens on that port (check by starting the service with a temporary `.env` in a scratch copy, not the real one, and asking `/health`; stop it afterwards).
